PROJECT ARCHITECTURE
================================================================================

The project is a .NET 8.0 application with four main layers:
- LeagueBuildTool.Core: All backend business logic, services, ML components
- LeagueBuildTool.App: Console application entry point with dependency injection
- LeagueBuildTool.UI: Blazor-based UI (minimal/starter implementation)
- LeagueBuildTool.Tests: XUnit test suite

Technology Stack:
- .NET 8.0
- ML.NET 4.0.3 (Microsoft.ML, Microsoft.ML.FastTree)
- Newtonsoft.Json 13.0.4
- Microsoft.Extensions.* (Configuration, DI, Hosting, Http)
- XUnit for testing

CURRENT BACKEND CAPABILITIES - BY DATA ELEMENT
================================================================================

1. ITEM RETRIEVER (RiotItemFetcher)
--------------------------------------------------------------------------------
WHAT IT ACHIEVES:
- Fetches all League of Legends items from Riot's Data Dragon CDN (no API key needed)
- Implements response caching to minimize API calls
- Converts Riot's JSON format to internal Item model
- Normalizes stat keys (e.g., "FlatHPPoolMod" → "Health")
- Derives tags from stats (AD, AP, Tank, Crit, AS, MS, etc.)

END RESULT DATA:
Item {
  Name: string (e.g., "Infinity Edge")
  Cost: int (gold)
  Description: string
  Stats: Dictionary<string, double> (normalized keys)
  Tags: List<string> (derived: AD, Crit, etc.)
}

METHODS:
- GetAllItemsAsync() - Returns List<Item> with all available items
- GetRiotItemDetailsAsync(itemName) - Get detailed info for specific item

STATUS: ✅ FULLY FUNCTIONAL AND TESTED


2. CHAMPION RETRIEVER (RiotChampionFetcher)
--------------------------------------------------------------------------------
WHAT IT ACHIEVES:
- Fetches all champions from Data Dragon (170+ champions)
- Loads basic champion data quickly for champion select scenarios
- Loads detailed data (abilities, lore, resource type) on demand for up to 10 champions
- Concurrent detail fetching with configurable semaphore (default: 8 concurrent)
- Normalizes base stats to canonical keys
- Detects resource types (Mana, Energy, Fury, etc.) from detailed data
- Derives tags from stats and Riot's champion tags

THREE METHODS:
1. GetAllChampionsAsync() - Full champion list with detailed resource detection
2. GetBasicChampionDataAsync() - Quick load for champion select (no detail fetching)
3. LoadChampionDetailsAsync(names) - Load details for specific champions (max 10)

END RESULT DATA:
Champion {
  Name: string
  Lane: string (empty by default, set by user)
  BaseStats: Dictionary<string, double> (10 canonical keys guaranteed)
  Tags: List<string> (Fighter, Mage, AD, AP, Resource:Mana, etc.)
  Gold: int
  Build: List<Item>
}

ChampionDetail {
  ParType: string (resource type: Mana, Energy, None, etc.)
  Title: string (e.g., "the Nine-Tailed Fox")
  Lore: string
  Abilities: List<ChampionAbility>
}

CANONICAL BASE STAT KEYS (Always Present):
- Health, AttackDamage, AbilityPower, Armor, MagicResist
- AttackSpeed, MoveSpeed, HealthRegen, Mana, ManaRegen

STATUS: ✅ FULLY FUNCTIONAL with smart caching and concurrent fetching


3. ML SYSTEM (BuildRecommender)
--------------------------------------------------------------------------------
WHAT IT ACHIEVES:
- ML.NET-based binary classification model
- Predicts build success probability based on game state
- Uses FastTree algorithm for training
- Feature engineering with one-hot encoding for categorical variables
- Feature normalization (MinMax)
- Model persistence (save/load from .zip file)

INPUT FEATURES:
BuildPredictionFeatures {
  ChampionName: string
  Role: string
  EnemyTeam: List<string>
  AllyTeam: List<string>
  EnemyDamageRatio: double (AP/AD ratio)
  TeamDamageRatio: double
  CurrentItems: List<string>
  CurrentGold: int
  GameTime: double (minutes)
  GoldDifference: int
  ObjectiveControl: double
}

TRAINING DATA STRUCTURE:
BuildTrainingExample {
  Features: BuildPredictionFeatures
  BuiltItems: List<string>
  WasWin: bool (label for training)
  Rank: string (Challenger, Master, Diamond, etc.)
  PatchVersion: string
  MatchId: string
  PerformanceMetrics: Dictionary<string, double> (KDA, damage, vision, etc.)
}

OUTPUT:
- Float probability (0.0 to 1.0) indicating predicted build success

METHODS:
- TrainModelAsync(trainingData) - Train model on collected match data
- PredictBuildSuccess(features) - Get prediction for current game state
- LoadModel() - Load previously trained model from file

STATUS: ⚠️ FRAMEWORK COMPLETE, MODEL NOT TRAINED
BLOCKER: Requires API key and training data collection


4. HIGH-ELO MATCH COLLECTOR (HighEloMatchCollector)
--------------------------------------------------------------------------------
WHAT IT ACHIEVES:
- Collects match data from Challenger/Grandmaster/Master/Diamond ranks
- Fetches player lists from ranked ladders
- Gets match history for each player
- Extracts build information, performance metrics, game outcomes
- Converts matches into ML training examples

COLLECTED DATA PER MATCH:
- Champion, role, items built (7 slots: item0-item6)
- Gold earned, game duration
- KDA (kills/deaths/assists)
- Damage dealt to champions, damage taken
- Vision score
- Win/loss outcome
- Patch version for relevance

TARGET RANKS: Challenger, Grandmaster, Master, Diamond

METHODS:
- CollectHighEloMatchesAsync(numberOfMatches) - Collect specified number of matches

API ENDPOINTS USED:
- /lol/league/v4/challengerleagues/by-queue/RANKED_SOLO_5x5
- /lol/match/v5/matches/by-puuid/{puuid}/ids
- /lol/match/v5/matches/{matchId}
- /lol/summoner/v4/summoners/{summonerId}

STATUS: ✅ COMPLETE IMPLEMENTATION
BLOCKER: ❌ REQUIRES RIOT API KEY TO FUNCTION

7. STAT MAPPER UTILITY (StatMapper)
--------------------------------------------------------------------------------
WHAT IT ACHIEVES:
- Normalizes Riot's inconsistent stat keys across API versions
- Maps 50+ variations to 12 canonical keys
- Derives high-level tags from stat distributions
- Detects resource types from raw key names

CANONICAL STAT KEYS (12 Total):
- Health
- AttackDamage
- AbilityPower
- Armor
- MagicResist
- AttackSpeed
- MoveSpeed
- HealthRegen
- Mana
- ManaRegen
- CritChance
- CritDamage

DERIVED TAGS:
- AD (Attack Damage focused)
- AP (Ability Power focused)
- Tank (High health/armor/MR)
- MS (Move Speed)
- AS (Attack Speed)
- Crit (Critical Strike)

RESOURCE DETECTION:
Detects: Mana, Energy, Fury, Rage, Heat, Chi, BloodWell

METHODS:
- NormalizeStatKey(riotKey) - Convert Riot key to canonical key
- DeriveTagsFromStats(stats) - Generate tags from stat dictionary
- DetectResourcesFromRawKeys(rawKeys) - Detect resource types

EXAMPLE MAPPINGS:
"flathppoolmod" → "Health"
"flatphysicaldmgmod" → "AttackDamage"
"abilitypower" → "AbilityPower"
"spellblock" → "MagicResist"

STATUS: ✅ FULLY FUNCTIONAL

NOTES FOR FUTURE DEVELOPMENT
================================================================================

When continuing work on this project, remember:

1. API KEY SETUP:
   - Get development API key from: https://developer.riotgames.com/
   - Store using: dotnet user-secrets set "RiotApi:ApiKey" "RGAPI-xxxxx"
   - Never commit API keys to version control

2. TESTING WITH API:
   - Development keys have rate limits (20 req/sec, 100 req/2min)
   - Be mindful of rate limits when collecting match data
   - Consider implementing rate limiting in code

3. ML MODEL TRAINING:
   - Start with 1000 matches for initial testing
   - Scale to 5000+ for production model
   - Collect from multiple patches for robustness
   - Balance win/loss examples in training data

4. BUILD PROVIDERS:
   - Check for official APIs first (unlikely for U.GG/OP.GG)
   - Web scraping: Use respectful delays, cache aggressively
   - Consider Terms of Service for each site

5. UI DEVELOPMENT:
   - Focus on backend completion first
   - UI can come after core features work
   - Consider whether Blazor Server or WASM is better
   - Mobile-responsive design from the start

6. DEPLOYMENT:
   - Environment variables for production API keys
   - Consider Azure App Service or similar for hosting
   - Redis for distributed caching if scaling
   - Monitor API usage to stay within rate limits
